# 项目评分表与自检清单

| 项 | 内容 |
|---|---|
| 用途 | 项目评价（40%）打分 + 学生自查 |
| 使用 | 学生先自检 → 教师按同一表评分（自检与评分差异 > 15 分需复议） |

---

## 第一部分 · 天工基线复现（20 分）

### 评分表

| 维度 | 权重 | 优秀（90+） | 合格（60–74） | 得分 |
|---|---|---|---|---|
| 功能完整性 | 30% | 全链路 + 3 类红线 + 降级全实现 | 主链路通，红线部分 | |
| 工程质量 | 25% | 分层清晰、有测试、无重复代码 | 能跑但耦合严重 | |
| 安全与合规 | 20% | 红线不可绕过、数据脱敏 | 有红线但存在绕过路径 | |
| 可观测与运维 | 15% | 指标 + trace + Runbook | 仅 print 日志 | |
| 文档与表达 | 10% | 文档齐全、讲解清晰 | 文档缺失较多 | |

### 自检清单（每条打 ✅ / ❌）

**功能**

- [ ] 下单 → 分解 → 审批 → 执行 → 证据，全链路可跑
- [ ] R1（禁入区）能被拦截
- [ ] R2（超载无令牌）能被拦截
- [ ] R4（停止区有人）能停机
- [ ] 降级至少能到 L2
- [ ] 技能四态（发布/审批/回滚）可用

**工程**

- [ ] 核心包不依赖基础设施（无 import sqlite/redis）
- [ ] 有 ≥ 3 个单测，且能证明"改坏会红"
- [ ] 没有复制粘贴的大段重复代码
- [ ] 有 README 说明如何运行

**安全**

- [ ] 红线判定在核心层（不在业务层/LLM 层）
- [ ] 令牌只能由人签发（接口不在模型可调用范围内）
- [ ] 数据使用脱敏合成数据
- [ ] 不存在"临时开启"类开关

**可观测**

- [ ] 有 `/healthz`
- [ ] 有指标端点（或至少结构化日志）
- [ ] 能用 trace_id 串起一次作业
- [ ] 有 Runbook（≥ 5 条）

## 第二部分 · 餐饮迁移项目（20 分）

| 维度 | 权重 | 判据 | 得分 |
|---|---|---|---|
| 场景真实性 | 20% | 需求来自真实门店痛点，用行业语言 | |
| 红线映射正确 | 25% | 五条全部改写，风险源对应准确 | |
| 闭环可运行 | 30% | 一条业务链端到端跑通 | |
| 证据链完整 | 15% | 照片/温度/时间戳可回放 | |
| 降级可用 | 10% | 至少 1 级可触发 | |

### 自检清单

- [ ] 作业单定义清晰（谁、何时、做什么、验收标准）
- [ ] 状态机覆盖正常与异常路径
- [ ] 五条红线有餐饮版表述（不含工厂术语）
- [ ] 一条链能从头跑到尾（派单→执行→证据→确认）
- [ ] 证据可回放（不是自动生成的一条记录）
- [ ] 至少一级降级可演示
