## 1. 写一个会失败的测试（红）

选一个现有功能（例：`check_geofence`），写一个**当前实现会失败**的测试：

```python
# tests/test_my_red.py
from tiangong_core import SafetyZone, ZoneKind
from tiangong_core.safety import check_geofence

def test_forbidden_zone_boundary():
    zones = (SafetyZone("Z1", ZoneKind.FORBIDDEN, 50, 50, 60, 60),)
    # 边界点 (50,50) 是否算禁入？先按你的理解写断言
    v = check_geofence(50, 50, zones)
    assert v.allowed is False, "边界点应视为禁入区"
```

```bash
PYTHONPATH="packages/tiangong_core;services/agent-runtime" pytest tests/test_my_red.py -q
```

**记录**：第一次运行结果 = ______（应为 failed）

## 2. 让它变绿

- 若你的断言是对的 → 改实现（或补充边界判定）；
- 若断言写错了 → 改测试（并说明为什么你的理解错了）。

**记录**：第二次运行结果 = ______（应为 passed）

> 关键：必须能证明"这个测试真的能失败"，否则它没有价值。

## 4. 改一条断言（业务真相）

把某条 E2E 断言从"元素存在"改成"数字一致"，例如：

```python
# 改前
expect(page.locator("#robots-body tr")).to_have_count(4)
# 改后（更强）
api = _api(base, "/tg-api/v1/robots")["robots"]
expect(page.locator("#robots-body tr")).to_have_count(len(api))
```

提交改动后的 diff。
