## 1. 三类故障注入

### 1.1 机器人执行失败（→ L1/L2）

```bash
# 方式一：混沌参数（演示脚本内置）
python tools/demo_run.py -- --chaos

# 方式二：手动让机器人离线后执行作业单
```

观察：重试次数、退避、是否升级到规则兜底。

### 1.2 规划器不可用（→ L2）

规则规划器是默认兜底。观察点：`RunReport.degrade_level` 是否从 `NONE` 变为 `L1/L2`，
以及任务是否仍然被分解出来（而不是卡在 PENDING）。

### 1.3 停止区有人（→ 停机，不是降级）

```bash
curl -s -X POST $BASE/tg-api/v1/work-orders/<ID>/run \
  -H 'Content-Type: application/json' -d '{"person_in_stop_zone": true}'
```

观察：`safety_halted`、任务 `FAILED`、速度归零。
