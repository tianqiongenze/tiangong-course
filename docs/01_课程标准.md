## 1. 课程定位

### 1.1 一句话定位

> 用一套真实工程基线，训练学生把智能体**从 Demo 做到可交付**的能力。

### 1.2 在专业课程体系中的位置

| 关系 | 课程 |
|---|---|
| 先修 | Python 程序设计、数据库原理与应用、Linux 基础、Web 前端基础 |
| 并行 | 机器学习应用、数据采集与预处理 |
| 后续 | 毕业设计、顶岗实习、1+X 证书考核 |

### 1.3 课程设计理念

1. **以真实项目为载体**：不是虚构案例，而是可运行、可测试、可压测的开源工程基线；
2. **以工作过程为主线**：需求→建模→实现→测试→运维→迁移，与岗位工作过程同构；
3. **以双元制为框架**：学校学原理、企业练真活，两场所共用量规；
4. **以认知科学为方法**：费曼输出 + 布鲁姆递进，确保"真会"而不是"好像会"。

## 2. 课程目标

### 2.1 总体目标

学生能够**独立完成一个中等规模智能体系统的需求分析、领域建模、核心实现、测试验证与运维交付**，
并能把方法论迁移到新场景；具备"安全优先、证据说话、可降级、可回滚"的职业习惯。

### 2.2 知识目标（K）

| # | 目标 | 可测量标准 |
|---|---|---|
| K1 | 说出具身智能体"大脑-小脑-脊髓"三层架构及职责边界 | 能画图并解释"为什么脊髓层不依赖 LLM" |
| K2 | 说明 EARS 需求语法与 SDD 规范驱动开发的四步 | 能写出 3 条合格 EARS 需求 |
| K3 | 掌握九态任务状态机与迁移白名单 | 能指出 3 个非法迁移并说明后果 |
| K4 | 理解五条安全红线的工程实现方式 | 能定位代码位置并解释拦截点 |
| K5 | 说明降级阶梯 L1–L4 的触发条件与处置 | 能对给定故障选择正确降级级别 |
| K6 | 理解 CQRS、预聚合、多级缓存的适用边界 | 能解释"为什么索引不能替代预聚合" |
| K7 | 掌握 REST / MCP / A2A / VDA 5050 的定位差异 | 能按场景选择协议并说明理由 |
| K8 | 理解测试金字塔与可观测三支柱 | 能设计一个含单测/E2E/压测的验证方案 |

### 2.3 能力目标（A）

| # | 目标 | 可测量标准 |
|---|---|---|
| A1 | 能编写符合规范的需求规格与验收标准 | 需求通过"可测试性"检查表 ≥ 90% |
| A2 | 能建立含不变量的领域模型并用测试守护 | 至少 3 条不变量有对应测试且能失败-通过 |
| A3 | 能实现带审批闸门与证据链的编排闭环 | 全链路跑通且证据 ≥ 3 类 |
| A4 | 能设计并验证降级路径 | 故障注入后系统按阶梯降级且可恢复 |
| A5 | 能对大数据量做查询优化（预聚合/缓存） | 聚合查询 P95 从秒级降到毫秒级 |
| A6 | 能接入多品牌设备（适配器模式） | 新增一个品牌适配器不改核心代码 |
| A7 | 能编写自动化测试与压测脚本 | 单测 + E2E + 压测三类齐备且通过 |
| A8 | 能按 Runbook 处置线上故障 | 故障注入演练 15 分钟内恢复 |
| A9 | 能把方法论迁移到新场景（连锁餐饮） | 迁移项目通过答辩评分 ≥ 70 |

### 2.4 素质目标（S）

| # | 目标 |
|---|---|
| S1 | **安全优先**：任何异常先停机后排查，不绕过红线 |
| S2 | **证据意识**：无证据不宣称完成 |
| S3 | **工程诚信**：不伪造测试结果、不隐藏缺陷 |
| S4 | **协作沟通**：能把技术方案讲给非技术者听懂（费曼） |
| S5 | **成本与合规意识**：知道数据不能出厂区/门店 |
| S6 | **持续改进**：每次复盘有可执行的改进项 |

## 5. 考核方案

### 5.1 成绩构成

| 部分 | 权重 | 说明 |
|---|---|---|
| 过程性评价 | **40%** | 16 次课的工作页（20%）+ 课堂费曼讲解（10%）+ 出勤与协作（10%） |
| 项目评价 | **40%** | 天工基线复现（20%）+ 餐饮迁移项目（20%） |
| 终结性答辩 | **20%** | 小组答辩 + 个人质询（评分表见 `assessment/答辩评分表.md`） |

### 5.2 过程性评价细则

| 项 | 观测点 | 满分 |
|---|---|---|
| 工作页完成度 | 16 份，按"完成/部分完成/未完成"计 2/1/0 分 | 20 |
| 费曼讲解 | 每次课抽 2–3 人，按"能讲清/能讲部分/讲不清"计 3/2/1 | 10 |
| 出勤与协作 | 迟到扣 0.5/次，缺勤扣 2/次；小组互评 | 10 |

### 5.3 项目评价细则

| 维度 | 权重 | 优秀（90+） | 合格（60–69） |
|---|---|---|---|
| 功能完整性 | 30% | 全链路 + 3 类红线 + 降级全实现 | 主链路通，红线部分实现 |
| 工程质量 | 25% | 分层清晰、有测试、无重复代码 | 能跑但耦合严重 |
| 安全与合规 | 20% | 红线不可绕过，数据脱敏合规 | 有红线但存在绕过路径 |
| 可观测与运维 | 15% | 有指标/日志/Runbook | 只有 print 日志 |
| 文档与表达 | 10% | 文档齐全、讲解清晰 | 文档缺失较多 |

### 5.4 答辩评分（20%）

见 `assessment/答辩评分表.md`：五个维度（问题理解 / 方案合理性 / 工程实现 / 安全与合规 / 表达与答辩），每维 20 分。

### 5.5 补考与重修

- 过程性评价不补；项目与答辩可补做一次（题目降级为"给定场景的最小实现"）；
- 红线相关能力（K4 A4）**必须单独通过**，否则整体不及格（安全一票否决）。

## 7. 质量保障

| 环节 | 措施 |
|---|---|
| 课前 | 环境预检脚本（`labs/L0_环境自检.md`），开课前一周完成 |
| 课中 | 每次课"三查"：任务书是否明确、学生是否动手、费曼是否讲清 |
| 课后 | 工作页批改 + 每周复盘（教师端记录共性问题） |
| 期末 | 答辩 + 课程目标达成度分析（每目标对应考核证据） |
| 迭代 | 每轮教学后更新 `docs/10_教师手册.md` 的"踩坑记录" |

### 7.1 课程目标达成度计算

```
达成度 = Σ(该目标对应考核点得分 × 权重) / Σ(满分 × 权重)
合格线：0.60；优秀线：0.85
```

每学期末填写 `assessment/达成度分析表.md`，作为下一轮改进依据。

## 8. 课程特色（申报用）

1. **真项目**：不是虚构案例，而是可运行、可压测、有 1 亿条数据的开源工程基线；
2. **双元制本土化三档模型**：解决"企业参与度不均"这一中国职教痛点；
3. **费曼 + 布鲁姆双驱动**：把"讲得清"作为掌握判据，可测量、可评分；
4. **安全一票否决**：红线能力单独考核，把职业习惯写进成绩；
5. **可持续同步**：课程与工程基线同源更新（`tools/sync_upstream.py`），不会教"过期技术"。
