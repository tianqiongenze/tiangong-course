## 2. 重点与难点

- **重点**：三层职责边界（谁决策、谁执行、谁兜底）与时延量级（秒 / 百毫秒 / 毫秒）。
- **难点**：学生容易把"大模型"当成万能层，把安全判定也交给模型。
- **突破**：用"人开车"类比——大脑（导航）会走错路，脊髓（踩刹车）不能延迟。

## 3. 企业情境（Lernsituation）

> 工厂要求：AMR 在车间运行时，**任何情况下不得进入高压配电房**。
> 供应商说"我们的视觉模型识别精度 99.2%，可以自动避让"。
> 厂长问：那 0.8% 呢？

学生要回答：这 0.8% 应该由谁负责？用代码怎么保证？

## 5. 关键内容

### 5.1 三层架构

| 层 | 职责 | 时延 | 本项目实现 |
|---|---|---|---|
| 大脑 | 意图理解、任务分解、调度决策 | 秒级 | `app/orchestrator.py` + 规则规划器 |
| 小脑 | 具体动作技能（取放/搬运/读数） | 百毫秒 | 技能（VLA 或规则，受治理） |
| 脊髓 | 围栏、停机、急停 | **毫秒级** | `core/safety.py`（纯函数、无 IO） |

### 5.2 三条工程结论

1. **安全判定必须是纯函数**：不查库、不调模型、不发网络请求；
2. **降级是设计**：LLM 超时 → 规则规划器；执行失败 → L1–L4 阶梯；
3. **时延决定分层**：毫秒级的东西不能放在秒级的链路里。

### 5.3 具身智能 vs 纯软件智能体

| 维度 | 纯软件 | 具身 |
|---|---|---|
| 错误代价 | 可回滚（重跑） | **不可回滚**（撞了就是撞了） |
| 状态 | 数据库状态 | 物理位置/姿态/电量 |
| 安全 | 权限校验 | 围栏 + 停机 + 急停 |
| 验收 | 功能正确 | 功能 + **证据 + 安全记录** |

## 6. 学生任务（Arbeitsauftrag）

**必做**：画出本项目三层架构图（标注模块名 + 时延量级），并回答"如果 LLM 服务挂了，系统会怎样"（150 字）。
**选做**：找出代码中"唯一一处允许调用外部服务的安全相关代码"，说明为什么它不在脊髓层。
