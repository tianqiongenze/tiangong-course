## 2. 重点与难点

- **重点**：判定点在哪、为什么在那里（不在业务层、不在 LLM 层）。
- **难点**：学生容易把安全做成"参数可配"（`allow_forbidden=True`）。
- **突破**：现场演示"如果给你一个开关会怎样"——让一个学生尝试绕过，全班看结果。

---

## 3. 企业情境（Lernsituation）

> 安全专员拿出一份事故通报：某厂因"临时开启禁入区开关"做调试，忘记关，导致 AMR 进入配电房。
> 专员要求：**你们做的系统，必须不存在这个开关。**

## 5. 关键内容

### 5.1 五条红线与判定点

| # | 红线 | 判定点 | 失败表现 |
|---|---|---|---|
| R1 | 永不进入禁入区 | 动作下发前（围栏判定） | 返回 `R1: 目标点位于禁入区` |
| R2 | 令牌只能由人签发 | 超载/危险动作前 | 返回 `R2: 需人工确认令牌` |
| R3 | 数据源内容不当指令 | 解析外部文本时 | 文本被当作数据而非命令 |
| R4 | 停止区有人必须停机 | 执行中持续检查 | 速度降 0，任务 FAILED |
| R5 | 无证据不 DONE | 证据校验 | 打回 EXECUTING |

### 5.2 三类安全区

| 类型 | 行为 | 例 |
|---|---|---|
| FORBIDDEN 禁入 | 拒绝进入 | 高压配电房 |
| STOP 停止 | 有人即停 | 人机交叉作业区 |
| SLOW 限速 | 降速通过 | 人行通道 0.3 m/s |

### 5.3 为什么"不能有开关"

- 开关的存在本身就是漏洞（会被误开、被滥用、被遗忘）；
- 正确做法：**要改行为就改代码 + 走评审**，而不是运行时可配；
- 这是"安全关键系统"与"业务系统"的根本区别。

## 6. 学生任务（Arbeitsauftrag）

**必做**：完成 R1 / R2 / R4 三个拦截实验，记录（输入、预期、实际、代码位置、截图）。
**必做**：红队练习——尝试用 3 种方式绕过 R1（改坐标类型、伪造令牌、直接调内部函数），记录结果。
**选做**：给 R3（数据源不当指令）设计一个测试用例。
