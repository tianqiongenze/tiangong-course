## 5. 关键内容

### 5.1 为什么索引不够（核心）

```
二级索引只存 (created_ts, rowid)。
7 天窗口命中 116 万行 → 每行按 rowid 回表取 status/duration →
116 万次随机读（5 GiB 文件）→ 173 秒。
```

预聚合：一次顺序扫描把结果算好，在线只读 1,365 行 → **0.23 毫秒**。

### 5.2 三级读取路径

| 层 | 命中耗时 | 说明 |
|---|---|---|
| L1 进程内 | ~2 ms | 无 IO |
| L2 Redis | ~19 ms（冷进程首击） | 跨进程共享 |
| 预聚合表 | ~0.3 ms | 缓存未命中时的兜底 |
| 明细表 | 秒级 | 只用于点查/回退 |

### 5.3 缓存的三个坑

| 坑 | 现象 | 对策 |
|---|---|---|
| 雪崩 | 大量 key 同时过期 | TTL 加随机抖动 |
| 穿透 | 查不存在的数据 | 空值缓存 / 布隆过滤 |
| 击穿 | 热点 key 过期瞬间打库 | 互斥重建 / 逻辑过期 |

### 5.4 真实踩坑（课堂必讲）

> L2 命中后回填 L1 时，如果用同一个 `set()` 会把 L2 的长 TTL 改成短 TTL，
> 预热几分钟就全失效。**回填 L1 不能改写 L2 的 TTL。**
