# 11 · 课程思政与职业素养

| 项 | 内容 |
|---|---|
| 原则 | **不贴标签、不喊口号**：思政点必须长在技术点上，能落到行为 |
| 载体 | 真实事故、真实代码、真实责任边界 |
| 评价 | 纳入"安全与合规""职业素养"维度，不单独加分 |

## 1. 八个思政映射点

| # | 技术点 | 思政主题 | 落点（行为） |
|---|---|---|---|
| 1 | 五条红线 | **生命至上、安全第一** | 拒绝"临时开启"开关；异常先停机 |
| 2 | 证据链 | **诚信、可追责** | 无证据不宣称完成；不篡改记录 |
| 3 | 审批闸门 | **责任意识** | 明白"机器不能签字，人能" |
| 4 | 降级阶梯 | **务实、可控** | 学会"退一步"，不硬撑到崩 |
| 5 | 数据合规 | **法治意识、隐私保护** | 数据不出厂区/门店；只用脱敏数据 |
| 6 | 适配器与标准 | **开放协作、尊重规则** | 遵守 VDA 5050 等公共标准 |
| 7 | 性能工程 | **工匠精神、精益求精** | 用数据说话，追求 0.23 ms |
| 8 | 迁移项目 | **创新与家国情怀** | 把技术服务中国实体产业（制造/餐饮） |

## 2. 三个"讲深一点"的思政场景

### 2.1 S05：安全红线（最重要的一次）

**事实**：工业机器人伤人事故中，相当比例源于"为调试方便临时关闭安全联锁"。

**提问链**：

1. 如果你是工程师，客户要求"加个开关方便调试"，你加不加？
2. 加了之后，谁负责？
3. 如果因为"方便"出了事故，代码能证明你提醒过吗？

**落点**：把"拒绝"变成可执行动作——**不提供开关，提供评审流程**。

### 2.2 S07：证据链与诚信

**事实**：验收时"说不清"往往不是技术问题，而是记录问题。

**提问链**：

1. "状态=DONE"能证明什么？不能证明什么？
2. 如果事后发现数据被改过，你怎么证明原样？

**落点**：证据只追加、不可修改；审计留痕。

### 2.3 S14：技术与中国产业

**事实**：中国制造业与连锁餐饮的数字化程度差异巨大，后者数字化基础更薄弱、需求更急。

**提问链**：

1. 为什么同一套方法，工厂能用，餐厅也能用？
2. 餐厅最怕什么？（食品安全、时效、人手）
3. 你的技术能帮上什么忙？

**落点**：技术不是炫技，是解决中国实体产业的真实问题。

## 3. 职业素养的五个可观测行为

| 素养 | 可观测行为 | 记录方式 |
|---|---|---|
| 守时 | 迟到次数 | 考勤表 |
| 诚信 | 是否伪造截图/数据 | 抽查 + 答辩质询 |
| 协作 | 小组互评 | 互评表 |
| 安全 | 是否绕过红线做"演示" | 代码审查 |
| 精益 | 是否主动优化（而非"能跑就行"） | 项目评分"工程质量"维度 |

---

## 4. 教师注意事项

1. **不空谈**：每个思政点必须配一个真实案例或一行代码；
2. **不双标**：教师自己演示时也不能"为了快"绕过审批；
3. **不扣帽子**：评价行为，不评价人品（"这次记录不完整" 而非 "你不诚实"）；
4. **留出口**：允许学生说"我做不到"，但要求说清"卡在哪"。
