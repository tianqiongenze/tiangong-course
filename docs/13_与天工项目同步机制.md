# 13 · 与天工项目同步机制

| 项 | 内容 |
|---|---|
| 目的 | 天工项目任何更新，都能**定位到课程里受影响的文件**，并留下同步记录 |
| 工具 | `tools/sync_upstream.py` |
| 原则 | 课程可以滞后，但**不能教过期数字**；滞后必须显式记录 |

---

## 1. 为什么需要机制（而不是"记得改"）

课程里引用了大量**会变的数字**：

| 数字 | 出现在 | 变了会怎样 |
|---|---|---|
| 测试数量（120 项） | README、docs/00、docs/08、S12 | 学生跑出 130 项，怀疑环境不对 |
| 覆盖率（93%） | README、docs/01、docs/06 | 评价标准失真 |
| 性能指标（173 s → 0.23 ms） | docs/00、S10、docs/06 | 实验结论对不上 |
| 数据规模（1 亿条 / 5.03 GiB） | docs/00、S09、S10 | 实验准备量估算错误 |
| 版本号（v1.2） | 全仓 | 引用错版本 |

靠"记得改"必然漏。因此用脚本扫描 + 清单核对。

---

## 2. 同步流程（每次天工发版后执行）

```bash
# 1. 拉取天工最新代码
cd ../Tiangong-EWA && git pull

# 2. 生成快照（自动提取版本、测试数、覆盖率、性能、文档索引）
cd ../Tiangong-Course
python tools/sync_upstream.py --tiangong ../Tiangong-EWA

# 3. 按脚本输出的"受影响文件清单"逐项核对
#    （脚本会把变更写入 upstream/CHANGELOG.md 与本文件 §4）

# 4. 更新受影响文档中的数字，重新导出
python tools/md_export.py

# 5. 提交
git add -A && git commit -m "sync: 同步天工 vX.Y（测试数/覆盖率/性能）"
```

## 3. 映射表：上游变更 → 课程文件

| 上游变更 | 受影响课程文件 | 更新内容 |
|---|---|---|
| 版本号 | `README.md`、`docs/00`、`docs/01`、`docs/13` | 基线版本 |
| 测试数量 / 覆盖率 | `README.md`、`docs/00`、`docs/06`、`docs/03/S12` | 数字与实验预期 |
| 新增/修改红线 | `docs/03/S05`、`docs/06` 题库、`docs/09/W05` | 用例与题目 |
| 状态机变化 | `docs/03/S04`、`docs/09/W04` | 九态图 |
| 性能指标变化 | `docs/03/S10`、`docs/06` 分析题、`docs/09/W10` | 对比数据 |
| 数据规模/脚本参数 | `docs/07` §5、`docs/03/S09` | 实验准备 |
| 接口变化（REST/MCP/A2A） | `docs/03/S11`、`labs/L5` | 调用示例 |
| 运维手册变化 | `docs/03/S13`、`labs/L6` | Runbook 与巡检项 |
| 新增文档（docs/46…） | `docs/12` 资源清单 | 索引 |

> 脚本会自动扫描上述文件中出现的**旧数字**并给出"疑似未更新"提示。

## 5. 快照文件说明（`upstream/`）

| 文件 | 内容 | 生成方式 |
|---|---|---|
| `upstream/snapshot.json` | 结构化快照（版本、commit、测试数、覆盖率、性能、文档清单） | `sync_upstream.py` |
| `upstream/天工项目快照.md` | 人读版（给教师看的一页纸） | 同上 |
| `upstream/CHANGELOG.md` | 每次同步的差异记录 | 同上（追加） |

**为什么要快照**：课堂可能离线；快照保证"课程与某个确定版本绑定"，
而不是"课程跟着 main 分支漂移"。

## 6. 同步检查单（打印贴在办公桌）

- [ ] `git pull` 天工最新代码
- [ ] 运行 `sync_upstream.py`
- [ ] 看脚本输出的"疑似未更新"清单
- [ ] 逐项核对 §3 映射表
- [ ] 更新 PPT 中涉及数字的页面（S10/S12 最常见）
- [ ] 重新导出 Word/PDF
- [ ] 在 §4 追加一行记录
- [ ] 提交并推送课程仓库

---

## 7. 反向同步（课程 → 天工）

课程使用中发现上游问题（文档错、示例跑不通），按以下方式回馈：

1. 在课程仓库提 issue，标注 `upstream`；
2. 若确认是上游缺陷，到天工仓库提 issue/PR；
3. 修复后回到 §2 流程同步。

> 课程不是"只读消费者"：教学是最好的测试，学生的困惑往往暴露文档缺陷。
