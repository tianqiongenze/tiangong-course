|---|---|

## 1. 为什么开这门课（产业判断）

### 1.1 产业侧的真实缺口

| 事实 | 对教学的含义 |
|---|---|
| 2026 年中国具身智能市场破万亿；工信部 + 国资委"实景实训"专项行动要求年底形成百个以上高价值场景 | 学生要有**场景落地**能力，不是只会调模型 |
| 行业共识：瓶颈不是"能不能干活"，而是"能不能**稳定、高效、可审计**地干活" | 课程重心必须是**工程化**（安全/证据/降级/可观测） |
| 企业招聘：会写 prompt 的人多，能把智能体**接进业务系统并验收**的人少 | 考核要能证明"能交付"，而不是"能演示" |
| 数据合规趋严（数据不出厂区/门店，需 consent） | 课程必须教**数据合规**与**脱敏** |

### 1.2 课程的价值主张

> **不教"再做一个更炫的 Demo"，教"把智能体做到能上线"。**

具体体现为五个"可"：**可解释、可降级、可审计、可回滚、可验收**。
这五个词贯穿 16 次课，也是最终答辩的评分主线。

## 2. 学情分析与对策

| 学生现状 | 风险 | 课程对策 |
|---|---|---|
| Python 会写脚本，但没做过工程分层 | 代码全塞一个文件 | 第 3–4 次课强制"核心包/服务层"分离，用目录结构约束 |
| 习惯"能跑就行" | 不写测试、不留证据 | 每次课交付物都要求"测试 + 证据"，无证据不算完成 |
| 对"安全"理解停留在口头上 | 认为红线是产品经理的事 | 第 5 次课用物理场景（禁入区/停机）让学生亲手触发拦截 |
| 没接触过真实数据规模 | 认为 1 万条和 1 亿条一样 | 第 10 次课现场对比"173 秒 vs 0.23 毫秒" |
| 表达弱，讲不清自己做了什么 | 面试吃亏 | 每次课末费曼环节 + 第 16 次课答辩，强制"讲给外行听" |

## 3. 课程结构：三段递进

```
第一阶段 · 认知与规范（S01–S04，16 课时）
  看懂一个真实平台 → 学会写规范 → 学会建模
  产出：需求规格（EARS）+ 领域模型（不变量）

第二阶段 · 工程实现（S05–S13，36 课时）
  安全红线 → 分解调度 → 编排闭环 → 降级 → 数据与性能 → 接口 → 测试 → 运维
  产出：可运行的天工基线复现 + 6 个实验报告

第三阶段 · 迁移与创造（S14–S16，12 课时）
  把方法论迁移到连锁餐饮 → 评审 → 答辩
  产出：餐饮智能体最小可行系统 + 答辩材料
```

**布鲁姆层级分布**（详见 `docs/05`）：

| 层级 | 课时 | 占比 | 主要落点 |
|---|---|---|---|
| 记忆 / 理解 | 8 | 12.5% | S01–S02 |
| 应用 | 24 | 37.5% | S03–S07 |
| 分析 | 20 | 31.3% | S08–S11 |
| 评价 | 8 | 12.5% | S12–S13 |
| 创造 | 4 | 6.3% | S14–S16（课后延伸） |

## 4. 双元制本土化模型（详见 `docs/04`）

### 4.1 两个学习场所

| 场所 | 占比 | 角色 | 做什么 |
|---|---|---|---|
| **学校**（学习领域 / Lernsituation） | 60%（约 38 课时） | 教师 = 学习陪伴者 | 原理、建模、代码、测试 |
| **企业**（实践任务 / Betrieblicher Auftrag） | 40%（约 26 课时，含课后） | 企业师傅 = 任务委托方 | 真实场景调研、需求确认、验收演练 |

> 本土化关键：**不照搬德国"企业为主"**。中国高职的现实是企业参与深度不均，
> 因此把"企业侧"设计成**可替代的三档**：
> A 档（有合作企业）——真实工单；B 档（校内实训基地）——仿真产线/门店；
> C 档（无企业资源）——用天工项目的脱敏场景 + 教师扮演"客户"。
> 三档共用同一套任务书与评分量规（`docs/08`）。

### 4.2 行动导向六步法（每次课的骨架）

```
Informieren（获取信息） → Planen（计划） → Entscheiden（决策）
   → Ausführen（实施） → Kontrollieren（检查） → Bewerten（评价）
```

对应到 4 课时的时间分配见 `docs/02` 与每次课教案。

## 5. 教学方法组合

| 方法 | 用在哪 | 具体做法 |
|---|---|---|
| 行动导向（六步法） | 每次课主体 | 任务书驱动，教师不先讲答案 |
| 费曼学习法 | 每次课末 15 分钟 | 学生两两互讲，讲不清的回炉 |
| 布鲁姆提问阶梯 | 课堂提问 | 同一知识点问 6 层（是什么/为什么/怎么用/哪里会错/怎么判断好坏/能否改造） |
| 对比教学 | S10、S12 | 173 秒 vs 0.23 毫秒；有测试 vs 无测试 |
| 故障注入 | S08、S13 | 现场制造失败，看降级与告警 |
| 项目制（PBL） | S14–S16 | 分组做餐饮迁移项目 |
| 复盘（After Action Review） | 每次课末 5 分钟 | 三个问题：发生了什么/为什么/下次怎么改 |

## 6. 学习路径（三类学生）

### 6.1 标准路径（大多数）

S01 → S02 → … → S16，每次课完成工作页 + 实验，最后参加答辩。

### 6.2 补基础路径（编程较弱）

- 课前补：Python 类与模块、JSON、HTTP 基础（提供 3 个 20 分钟微课）
- 课中：实验只做"必做项"，选做项改为观摩
- 评价：允许用"讲解 + 图示"替代部分编码（量规中"表达"维度加权）

### 6.3 拔高路径（学有余力）

- 选做：把天工的 VDA 5050 适配器接到真实 AMR（校内实训室）
- 选做：给餐饮迁移项目加"多门店联邦调度"
- 产出：可投稿校级/省级技能竞赛作品

## 8. 教学条件

| 类别 | 要求 |
|---|---|
| 机房 | 每人 1 机（8 GB 内存以上，20 GB 磁盘余量）；教师机可投屏 |
| 软件 | Python 3.12+、VS Code、Git、浏览器（Chrome/Edge）、终端 |
