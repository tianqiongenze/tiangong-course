> 使用说明：本表是**教师排课与进度控制**的主表；每次课的逐分钟设计见 `docs/03_教学方案/S01–S16`。

## 2. 每次课的四课时结构（通用模板）

| 课时 | 阶段（六步法） | 内容 | 时长 |
|---|---|---|---|
| 第 1 课时 | Informieren 获取信息 | 情境导入（企业案例/故障视频）→ 任务书下发 → 关键概念讲解 | 45 min |
| 第 2 课时 | Planen + Entscheiden | 小组拆解任务、画方案、定分工、教师点评纠偏 | 45 min |
| 第 3 课时 | Ausführen 实施 | 动手编码/配置/实验，教师巡回指导 | 45 min |
| 第 4 课时 | Kontrollieren + Bewerten | 自检清单 → 交叉验证 → **费曼讲解** → 量规评分 → 复盘与作业 | 45 min |

> 变体：S05/S08/S13 为"故障注入"型，第 3 课时改为演练；S14–S16 为"项目工作坊"，第 2–4 课时合并使用。

## 3. 分次课要点（教师速查）

### S01 课程导入与双元制契约
- **一句话**：这门课不教"炫技"，教"能上线"。
- **关键动作**：展示一个真实故障（红线拦截失败会怎样）→ 建立敬畏 → 签学习契约。
- **产出**：学习契约（学生签名）、个人目标卡（想达到的 3 个能力）。
- **作业**：读天工 README，跑通 `make demo`（或 `python tools/demo_run.py`），截图。

### S02 具身智能与智能体三层架构
- **一句话**：大脑会出错，脊髓不能出错。
- **关键动作**：把"大脑/小脑/脊髓"映射到代码目录，让学生找出 safety.py 的位置。
- **产出**：三层架构图（手绘即可）+ 场景卡（一个可被替代的重复作业）。
- **作业**：用 200 字说明"为什么安全判定不能交给大模型"。

### S03 需求工程：EARS 与 SDD
- **一句话**：写不出可测试的需求，就写不出可验收的系统。
- **关键动作**：把一句"系统要安全"改写成 3 条 EARS 需求。
- **产出**：需求规格 v0.1（≥ 8 条，含验收标准）。
- **作业**：给同学的需求挑刺（找出 2 条不可测试的）。

### S04 领域建模：不变量与九态状态机
- **一句话**：模型的价值在于"什么不能发生"。
- **关键动作**：画九态图，标出 3 个非法迁移；写一个能抓住非法迁移的测试。
- **产出**：领域模型 + 3 条不变量测试（必须能失败再通过）。
- **作业**：给餐饮场景设计一个状态机（草稿）。

### S05 安全红线：围栏/令牌/停机
- **一句话**：红线不是文档，是代码里的一行 `raise`。
- **关键动作**：现场触发 R1（禁入区）、R2（超载无令牌）、R4（停止区有人）。
- **产出**：红线拦截实验报告（3 个用例 + 截图 + 代码位置）。
- **作业**：找出系统中"最可能被绕过"的一处并写改进方案。

### S06 任务分解与机群调度
- **一句话**：分解要可执行，调度要可解释。
- **关键动作**：给定作业单，手写 DAG；对比规则规划器输出；解释打分。
- **产出**：调度方案 + 能力匹配单测。
- **作业**：设计一个"两台机器人抢一个充电桩"的调度规则。

### S07 编排闭环：审批闸门与证据链
- **一句话**：没有证据的完成，等于没完成。
- **关键动作**：画出时序图；故意跳过审批看系统怎么拦；删一条证据看任务是否 DONE。
- **产出**：闭环时序图 + 证据链说明 + 一次完整演示。
- **作业**：为"证据缺失"设计一条更友好的提示。

### S08 降级阶梯与异常处置
- **一句话**：降级不是失败，是可控的退让。
- **关键动作**：混沌注入（机器人失败）→ 观察 L1→L4；讨论"什么时候该 L4"。
- **产出**：降级演练报告（含触发条件、现象、恢复步骤）。
- **作业**：给餐饮场景设计降级阶梯（外卖爆单/骑手不足）。

### S09 数据层：业务库/分析库与 CQRS
- **一句话**：写要稳，读要快，两者不该挤在一个库里。
- **关键动作**：对比业务库与分析库的表结构与体量；解释读写分离的语义价值。
- **产出**：数据分层设计图（业务库/分析库/缓存三层）。
- **作业**：列出 3 个"必须走主库"的读场景。

### S10 性能工程：预聚合与多级缓存
- **一句话**：索引不等于快，聚合要预计算。
- **关键动作**：现场跑 1 亿条：明细聚合 173 秒 → 预聚合 0.23 毫秒；再开缓存看命中率。
- **产出**：性能对比报告（含数据表与结论）。
- **作业**：设计一个"缓存穿透"的防护方案。

### S11 接口与多品牌接入
- **一句话**：协议是别人的，契约是自己的。
- **关键动作**：用 REST / MCP / A2A 各调一次；读 VDA 5050 报文；新增一个假品牌适配器。
- **产出**：三协议调通记录 + 适配器代码（不改核心）。
- **作业**：说明"为什么适配器只做翻译，不做决策"。

### S12 测试工程：TDD/BDD/E2E
- **一句话**：先写一个会失败的测试，才知道自己在做什么。
- **关键动作**：红-绿-重构；用 Playwright 跑一次 E2E；看一次压测报告。
- **产出**：测试用例集（单测 + 1 个 E2E + 1 个压测脚本）。
- **作业**：给"看板与 API 不一致"设计一个 E2E 断言。

### S13 可观测与运维值班
- **一句话**：线上出问题时，你只有日志和 trace。
- **关键动作**：按 trace_id 还原一次故障；按 Runbook 处置一次注入故障。
- **产出**：个人 Runbook（≥ 8 条故障处置）。
- **作业**：为"缓存命中率骤降"写一条告警规则。

### S14 迁移项目启动：连锁餐饮建模
- **一句话**：换场景不换方法。
- **关键动作**：把工厂的"五条红线"改写成餐饮版；画出餐饮作业单与状态机。
- **产出**：餐饮场景模型 + 红线映射表。
- **作业**：完成需求规格 v0.1（餐饮）。

### S15 迁移项目实施与中期评审
- **一句话**：能跑通一条真实业务链，才算 MVP。
- **关键动作**：实现"门店巡检/后厨配送/外卖调度"其一；中期评审（同伴 + 教师）。
- **产出**：MVP + 评审记录 + 改进清单。
- **作业**：按评审意见修复并准备答辩。

### S16 答辩、复盘与职业发展
- **一句话**：讲不清，就是没做成。
- **关键动作**：8 分钟答辩 + 5 分钟质询；复盘；职业路径讲解（1+X / 岗位 / 竞赛）。
- **产出**：答辩材料 + 个人复盘报告。
- **作业**：提交完整项目包（代码 + 文档 + 演示视频）。

## 4. 进度控制与弹性

| 风险 | 信号 | 处置 |
|---|---|---|
| 环境问题拖慢 | S01 有 > 30% 学生跑不通 | 启用 `labs/L0` 预检 + 助教一对一；S02 压缩 20 分钟补环境 |
| 编程基础弱 | S04 不变量测试写不出 | 提供"填空式"测试模板；降低选做要求 |
| 进度超前 | S10 提前完成 | 加"缓存穿透/雪崩"专题讨论 |
| 进度滞后 | S08 未完成降级演练 | 把 S11 的 A2A 内容改为自学，保 S12 测试课 |
| 企业资源缺失 | A 档无法落实 | 切 B/C 档（见 `docs/04` §3），任务书不变 |

**红线**：无论进度如何，**S05（安全红线）与 S07（证据链）不可压缩**——这是课程的价值底线。

## 5. 作业与工作量估算

| 类型 | 频次 | 单次时长 | 总时长 |
|---|---|---|---|
| 课后作业（工作页） | 16 次 | 40–60 min | 约 13 h |
| 实验报告 | 6 次 | 60–90 min | 约 7 h |
| 迁移项目 | 3 周 | 6–8 h/周 | 约 20 h |
| 答辩准备 | 1 次 | 3 h | 3 h |

合计课外约 **43 小时**，符合 4 学分课程"课内外 1:1"的常规要求。
